# Tone of voice

Rules for all text on a Hoxton slide: headings, body, lists, labels and covers. Read this file before writing any slide copy, and check every slide against it before handover.

Shoreditch Design is a service business. Slide copy that reads as machine-written makes the studio look cheap, so these rules are strict. When a rule here conflicts with another instruction in this skill, this file wins.

## Register

- Formal and professional, as in a pitch to a client or a briefing to a team. Not conversational and not chatty.
- The slide is a reference, not a script. The presenter supplies the reasons, the context, the examples and the persuasion out loud or in the presenter notes.
- A viewer must understand the point of the slide within 3 seconds (Duarte's glance test).
- Presenter notes (`<aside class="notes">`) may use the presenter's own spoken voice. Slide text may not.

## Headings

- Use a noun label of 1 to 3 words, such as "Developer briefing", "Figma file" or "Technical discovery".
- Use sentence case. Do not use a verb, a full stop or a question.
- Do not write sentence titles or lines of dialogue, such as "Here is how we hand over a site" or "Why the file matters".
- Use "and", not "&".
- Do not put a subheading or lede under a heading when it only explains the heading. A lede is allowed only when it gives a fact that the heading and body do not, such as a date, a scope, a figure or a named tool.

| Heading | Rejected lede | Why |
|---|---|---|
| Developer briefing | A call with the freelancer before any build work starts. | Restates the heading. |
| Figma file | Every handoff file meets these standards before it goes to a developer. | Restates the obvious. |
| Technical discovery | Ask these questions during design. The answers shape the information architecture. | Restates the slide, and the claim is wrong. |
| QA and feedback | All QA runs through Feedbucket. | Acceptable only when the tool name appears nowhere else on the slide. Otherwise, cut it. |

## Body text

- Write only what the presenter cannot say faster: specifications, criteria, names, tools, figures and responsibilities.
- Use full, plain, declarative sentences in the active voice, with no more than 25 words in each sentence. Name who does the action.
- Do not chop a thought into short fragments, such as "Check the file. Name the layers. Ship it." Join related clauses with "and", "so" or "which".
- Do not use narrative, transitions, recaps or closing summaries.
- Use the present tense for standards and the imperative for steps. Do not make promises in the future tense.
- Do not use negative contractions. Write "cannot", not "can't", and "do not", not "don't".

## Lists

- Every item in a list uses the same grammatical form: all noun phrases, or all imperatives.
- Do not start an item with a bold label followed by a colon, as in "**Webflow:** back up the site". Write the label as part of the sentence instead: "For Webflow, back up the site before the transfer".
- Number a list only when the order matters.
- Do not group items in threes to look thorough. Use as many items as the content has.

## Terms

- Use one term for each concept, and use it throughout the deck. Do not swap in a synonym for variety. If the deck says "freelancer", it never says "dev", "engineer" or "contractor".
- Use the client's terms and product names exactly as the client writes them.
- Write every number as a numeral (2 days, 4pt grid), and use a comma in numbers above 999 (1,200).

## Banned patterns

These patterns mark text as AI-written. Do not use any of them on a slide.

| Pattern | Example of what not to write |
|---|---|
| Negative parallelism: deny one idea, then state another | "This is not a handoff, it is a partnership." / "Not X, but Y." |
| Colon reveal | "The result: fewer revisions." |
| Em-dash aside | "Every file — no exceptions — is checked." |
| Explainer lede that restates the heading | See the table under Headings. |
| Vague significance | "shapes the architecture", "plays a key role", "ensuring quality", "is essential" |
| Rule of three for effect | "Fast, flexible and future-proof." |
| Fragments for drama | "Clear files. Fewer bugs. Happy developers." |
| Sentences of the same short length in a row | "Set the deadline. Confirm the date. Update the client." |
| Second-person pep | "You've got this." / "Make it count." |
| Chatbot phrasing | "Here's the thing", "Let's dive in", "It's worth noting" |
| Copula avoidance | "serves as", "stands as", "boasts" in place of "is" or "has" |
| Hedging | "may potentially", "in some cases", "arguably" |
| False range | "From typography to trust." |
| Unattributed claims | "Experts agree", "Studies show" with no source |
| Promotional or inflated language | "a testament to", "groundbreaking", "vibrant", "world-class" |
| Title case and emoji | "Our Design Handoff Process 🚀" |
| Recap or closing line | "In short, a good handoff saves time." |

### Banned words

delve, robust, seamless, leverage, crucial, pivotal, streamline, elevate, unlock, empower, foster, facilitate, showcase, underscore, landscape, journey, tapestry, testament, transformative, holistic, synergy, cutting-edge, game-changer, best-in-class, utilise, key (as an adjective), deliver (as a vague verb), ensure (as filler).

## Final check

Read each slide aloud before handover.

- If a line sounds like something a person would never say in a client meeting, rewrite it.
- If a line repeats the heading, delete it.
- If a line claims that something matters without saying what it changes, delete it, or replace it with the fact.
